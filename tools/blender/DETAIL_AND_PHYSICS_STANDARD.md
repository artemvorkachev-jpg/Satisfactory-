# Стандарт детализации и физики моделей

## Единая художественная система

- Масштаб: 1 Blender unit = 1 метр.
- Базовая палитра промышленности: графитовый/тёмная сталь, оранжевые акценты, сигнальный жёлтый, ограниченный бирюзовый цвет экранов.
- Материалы разделяются на окрашенный металл, необработанную сталь, резину, стекло, светящиеся индикаторы, пластик, органику и минералы.
- Цвета предметов и природы сохраняют собственную материальную идентичность; промышленная палитра не применяется к ним механически.
- Детали добавляются только после утверждения пропорций и общего силуэта.

## Этапы на каждый объект

1. Сопоставить все четыре варианта A/B/C/D.
2. Выбрать один вариант по силуэту, читаемости, пропорциям, палитре и сочетаемости с соседними объектами.
3. Проверить модель в масштабе игрока и рядом с объектами, к которым она подключается.
4. Доработать силуэт, панели, крепления, кабели, порты, кромки, болты и функциональные детали там, где они оправданы.
5. Настроить PBR-материалы и UV; не использовать чрезмерно мелкие детали, которые не видны на телефоне.
6. Создать LOD и проверить бюджет геометрии/материалов на мобильном Safari.
7. Экспортировать GLB и проверить его в игровом мире.

## Физические профили

| Тип объекта | Физическая модель |
|---|---|
| Производственное здание | Неподвижный compound collider; отдельные зоны взаимодействия и порты |
| Фундамент/стена/балка | Простой box/convex collider, snap points |
| Конвейер/труба | Тонкий статический collider; поток предметов симулируется отдельно |
| Предмет на ленте | Kinematic collider или визуальный объект на кривой; не создавать тяжёлую физику для каждого предмета |
| Ресурсный узел | Статический collider с отдельной зоной добычи |
| Транспорт | Dynamic rigid body, колёса/подвеска и ограничение скорости |
| Существо | Capsule/compound collider, навигационная форма и отдельные триггеры |
| Флора | Статический простой collider либо отсутствие коллизии для мелких растений |
| Экипировка/предмет в руке | Без мирового collider; отдельные точки крепления к персонажу |

## Требования к физике

- Не использовать mesh collider высокой детализации для каждого объекта.
- Коллизии должны быть независимы от визуального LOD.
- Производственные порты, точки соединения и snap points хранятся как именованные узлы.
- Предметы на конвейерах не должны сталкиваться друг с другом как полноценные rigid bodies: поток управляется логистической симуляцией.
- Транспорт и игрок используют физику с фиксированным timestep; производственные процессы используют отдельную детерминированную симуляцию.
- На мобильном устройстве ограничивать количество динамических тел, обновление теней и число draw calls.
- Каждый collider проверяется в сцене: нет проваливания сквозь пол, застревания в дверях, пересечения соседних машин и ложных блокировок портов.

## Статусы

`blockout` → `variant-reviewed` → `detail-pass` → `materials` → `collider-ready` → `LOD-ready` → `mobile-tested` → `approved`.

Ни один объект не помечается как полностью готовый до проверки в реальной игровой сцене на мобильном устройстве.

## Runtime implementation status — 2026-11-14

- Rapier 3D compatibility runtime is connected to the browser game.
- The player uses a dynamic capsule body with gravity, ground contact and jump velocity.
- The HUB, production-machine GLBs and the three starter resource-node GLBs receive static AABB colliders from their world-space model bounds.
- This is a first collision pass, not final per-part physics. Vehicle suspension, moving machine parts, compound colliders, exact interaction volumes and all remaining assets are still pending.
- The visual meshes remain independent of collision shapes. This keeps the mobile rendering path lighter and lets collision proxies be refined without rebuilding visual geometry.
